    02 — UNDER THE MAP

    A route is a graph problem.

    Vertices are street points. Edges connect them. Dijkstra finds the smallest sum of edge weights.

    1. Model the campus

    G = (V, E) is a directed, weighted graph. Each vertex is an OSM street point. Each permitted way segment is an edge, weighted by the Haversine distance between its endpoints.

    Two-way streets have an edge in each direction. Vehicle routes respect one-way streets. Walking uses its own access profile.

    2. Relax the edges

    d(v) ← min(d(v), d(u) + w(u,v))

    Start with d(s) = 0; all other distances are ∞. Repeatedly settle the vertex with the smallest tentative distance and update its neighbours. Stop when the destination is settled.

    3. Read the result

    Follow predecessor pointers backwards to reconstruct the path. All weights are non-negative, so every settled distance is final.

    Python’s heapq implements the min-priority queue. Duplicate heap entries are skipped when stale: O((|V| + |E|) log |E|) time with O(|V| + |E|) space.

    A fare is calculated after distance minimisation: base + max(0, distance in km − included km) × extra rate. The project does not optimise live traffic, fares across different providers, or multiple-stop tours.

    PROJECT NOTES

    The streets behind the shortest path.

    The routing algorithm runs in Python. The map uses Leaflet with OpenStreetMap tiles. Overpass provides the street graph, which is saved locally after the first successful download.

    Public route mode uses OSRM foot/driving geometry, not the local Dijkstra trace. Metro/bus have no verified route, fare or timetable. For auto and metered non-AC black/yellow taxi, daytime distance-based estimates use the Delhi Transport 2023 fare order; check DMRC fares independently. Nothing here is a live quote.

    Landmark pins are approximate. The algorithm routes between nearby usable street vertices; dashed connectors are straight-line access gaps, excluded from distance, time, and fare. Check entrances locally.

    This is a student routing model: it filters access tags and one-way streets but does not model turn restrictions, opening hours, traffic, or e-rickshaw-specific road regulations. Both paid modes use the same basic motor-vehicle profile. Walking and all fares are estimates.

    The offline sample graph has 12 vertices with invented classroom weights. Its lines are illustrative connections, not navigation directions.
