    02 — UNDER THE MAP

    A route is a graph problem.

    Vertices are street points or transit stops. Edges connect them. Dijkstra finds the smallest sum of edge weights.

    1. Model the campus

    G = (V, E) is a directed, weighted graph. Walking uses street points and segments. Bus and metro use stops and directed service connections reconstructed from OSM route relations.

    Walking edges use metres. Bus and metro journeys add street based walking access to mapped stops, then use minutes as Dijkstra weights. Transit connections retain the underlying way geometry. A road alone does not imply that a bus runs on it.

    2. Relax the edges

    d(v) ← min(d(v), d(u) + w(u,v))

    Start with d(s) = 0; all other distances are ∞. Repeatedly settle the vertex with the smallest tentative distance and update its neighbours. Stop when the destination is settled.

    3. Read the result

    Follow predecessor pointers backwards to reconstruct the path. All weights are non-negative, so every settled distance is final.

    Python’s heapq implements the min-priority queue. Duplicate heap entries are skipped when stale: O((|V| + |E|) log |E|) time with O(|V| + |E|) space.

    Walking routes minimise street distance. Bus and metro journeys minimise estimated time, including mapped walking access and a boarding allowance. Ticket estimates use only ride distance; a bus service change adds a ticket. Live departures and concessions are not modelled.

    PROJECT NOTES

    The streets behind the shortest path.

    The routing algorithm runs in Python. The map uses Leaflet with OpenStreetMap tiles. The OpenStreetMap map API provides a small campus extract; a lightweight Overpass street query is a fallback. Transit data is requested separately. Successful data is saved locally.

    Landmark pins are approximate. The algorithm routes between nearby usable network vertices. Access gaps are reported in metres but never drawn as roads or walking paths; they are excluded from distance, time, and fare. Check entrances locally.

    Walking routes use allowed streets. Bus and metro routes require explicit OSM route relations with connected geometry and ordered stops. Missing services are reported, never inferred from roads. Landmark access gaps, platform access, turn restrictions, opening hours and live schedules are not modelled. Time and ticket fares are estimates.

    The offline maths example uses a separate abstract graph diagram, with no geographic coordinates or map polylines. Actual road routing requires downloaded or imported OSM streets; the saved street cache also works offline.
